# MatchLens AI — Sports Commentary Auto-Tagger & Highlight Generator
 
End-to-end sports commentary pipeline combining NLP classification and LLM-powered
summarization to automate match highlight generation for sports streaming platforms.
 
**[ Try the live app → PASTE_YOUR_HUGGINGFACE_SPACE_LINK_HERE ]**
 
---
 
## What It Does
 
Paste raw football commentary text → get instant multi-format match highlights:
 
- **Full Summary** — 150-200 word match narrative for editorial teams
- **Executive Summary** — 2-3 sentences for match result cards
- **Push Notification** — under 120 characters for mobile alerts
- **Player of the Match** — name and rationale
- **Key Moments** — structured JSON for VOD chapter markers
Every output passes through a post-generation **guardrail** that cross-checks the
LLM's claims (goal counts, scorer names, red cards) against deterministically
computed facts from the source data — before anything is shown to the user.
 
---
 
## Architecture
 
```
Raw Commentary Text
        ↓
Text Segmentation (regex — handles multiple commentary site formats)
        ↓
TF-IDF + Linear SVM Classifier (11 event classes)
        ↓
Impact Filtering (Goals, Red Cards, Penalties, Yellow Cards)
        ↓
Ground-Truth Fact Computation (scorer counts, braces, hat-tricks, red cards)
        ↓
LLaMA-3.1-8B-Instant via Groq (multi-format generation, facts injected as hard constraints)
        ↓
Post-generation Guardrail (PASS / WARN / FAIL fact verification)
        ↓
Full Summary | Executive Summary | Push Notification | Player of Match | Key Moments JSON
```
 
The deployed app runs **FastAPI + Streamlit in a single Docker container** on
Hugging Face Spaces, with classifier artifacts pulled from the Hugging Face Hub
at container startup (kept out of the git repo).

## Event Classification
 
| Model | F1 Weighted | F1 Macro | Notes |
|---|---|---|---|
| TF-IDF + Logistic Regression | 0.9992 | 0.9897 | Keyword exploitation |
| TF-IDF + Linear SVM | 0.9993 | 0.9901 | **Strongest classical model — used in production** |
| BERT fine-tuned | 0.9997 | 0.9971 | Match-level split |
 
**Key insight:** Classical TF-IDF models match BERT performance on this dataset
because sports commentary contains explicit lexical triggers ("yellow card shown
to...", "scores from the penalty spot"). The transformer's advantage is marginal
overall but more meaningful on ambiguous events like distinguishing a red card
from a tackle description. Given the negligible accuracy gap and the inference-cost
difference, **TF-IDF + SVM was chosen for production** — a deliberate
accuracy-vs-latency tradeoff, not a default.

## LLM Fine-Tuning Experiment: QLoRA on LLaMA-3-8B
 
To explore whether a smaller open model could close the quality gap with a larger
teacher model, a **teacher-student distillation** experiment was run using QLoRA.
 
### Setup
 
| | |
|---|---|
| **Teacher model** | `openai/gpt-oss-120b` via Groq (generates high-quality training targets) |
| **Student model** | `meta-llama/Meta-Llama-3-8B-Instruct`, fine-tuned with QLoRA (4-bit NF4, LoRA r=16) |
| **Training data** | 402 match summaries generated by the teacher model, formatted as instruction-tuned chat examples |
| **Train / Val split** | 361 / 41 (90/10 split after a token-length filter) |
| **Eval set** | 200 matches, held out and **never seen during training** |
| **Hardware** | Google Colab Pro, NVIDIA A100 (40GB) |
| **Trainable parameters** | 13.6M / 8.04B (0.17% of total — LoRA adapter only) |

<!--After filtering for token length (≤2800 estimated tokens, to fit
training context) and JSON parse success, 402 usable examples remained for
fine-tuning.
-->

**Eval set isolation logic:** before any training data was generated, 200 match
IDs were randomly sampled (fixed seed) and excluded from the teacher-generation
pool entirely. This guarantees the post-fine-tuning evaluation measures
generalization, not memorization — the model is being tested on matches it has
never been trained or distilled on.

**Training data selection logic:** training data selection was stratified, not
random, to avoid a model that only learns to summarize routine 1-0 wins. From
the remaining match pool (eval IDs excluded), matches were bucketed by **score
margin** (close / comfortable / blowout) and **red card presence** (yes / no),
then sampled across all six resulting strata — 402 matches in total — so the
training data reflects a representative spread of match narratives rather than
just the most common pattern in the dataset. These 402 matches were sent to the teacher model to generate target summaries.


### Results: Baseline LLaMA-3-8B vs QLoRA Fine-Tuned, on the same 200-match eval set
 
| Metric | Baseline (pre-QLoRA) | Fine-tuned (post-QLoRA) | Delta |
|---|---|---|---|
| ROUGE-1 | 0.2726 | 0.3718 | **+0.0992 (+36%)** |
| ROUGE-2 | 0.0850 | 0.1486 | **+0.0636 (+75%)** |
| ROUGE-L | 0.1926 | 0.2651 | **+0.0725 (+38%)** |
| BERTScore F1 | 0.1954 | 0.2630 | **+0.0676 (+35%)** |
| Goal scorer recall | 0.988 | 0.973 | ≈ unchanged |
| Red card recall | 0.982 | 0.994 | ≈ unchanged |
| Guardrail PASS rate | 58.0% | **95.3%** | **+37.3pp** |
| Guardrail FAIL rate (hallucinations) | 8.5% | **4.7%** | **-3.8pp** |

<!-- 
> Note: the post-QLoRA eval successfully parsed valid JSON for 192/200 matches
> (8 generations failed JSON parsing — a known small-model failure mode). Metrics
> above are computed on the 192 that parsed.
-->
**What this shows:**
 
- **ROUGE and BERTScore both moved together** — the fine-tuned model didn't just
  learn to copy more of the input (which ROUGE alone could reward); BERTScore
  confirms the *semantic* quality of the summaries improved too.
- **The guardrail PASS rate is the most production-relevant number.** Going from
  58% → 95.3% means the difference between "1 in 3 outputs need manual review"
  and "the vast majority are safe to auto-publish." This is the metric that
  would matter most to an editorial team.
- **Event recall stayed flat — and that's expected, not a weakness.** Recall is
  driven by the ground-truth facts injected into the prompt at inference time,
  not by the model's learned writing style. Fine-tuning improves *how* the model
  writes, not *what facts* it has access to.
### Why the fine-tuned model isn't used in the live deployed app
 
This was a deliberate infrastructure tradeoff, not an oversight. Serving a
fine-tuned 8B model requires persistent GPU inference — Hugging Face Spaces'
free tier is CPU-only, and paid GPU hosting costs real money for a portfolio
project with near-zero production traffic.
 
Instead, the **distilled learnings were carried into the production prompt** as
few-shot examples: 3 hand-vetted, fact-consistent outputs from the QLoRA training
data (covering a high-scoring match, a low-scoring draw, and a match with a red
card) are embedded directly in the system prompt sent to the base
`llama-3.1-8b-instant` model via Groq's free, low-latency API.

## Tech Stack
 
- **Classification:** TF-IDF + LinearSVC (scikit-learn)
- **LLM (production):** LLaMA-3.1-8B-Instant via Groq API, with few-shot prompting
- **LLM (fine-tuning experiment):** LLaMA-3-8B-Instruct + QLoRA (PEFT, bitsandbytes, TRL)
- **Teacher model:** `openai/gpt-oss-120b` via Groq
- **Evaluation:** ROUGE (rouge-score), BERTScore, custom event-recall and fact-verification guardrail
- **Backend:** FastAPI
- **Frontend:** Streamlit
- **Artifact storage:** Hugging Face Hub (classifier + adapter weights, kept out of git)
- **Deployment:** Docker + Hugging Face Spaces
- **CI/CD:** GitHub Actions
- **Training compute:** Google Colab Pro (A100)

## Data
 
European football commentary dataset — 941,009 events across 9,074 matches from
5 leagues (2011–2017). Source: `events.csv` + `ginf.csv` (Kaggle). Events were
enriched with natural-language descriptions and impact scores to build training
timelines for both the classifier and the LLM stages.
